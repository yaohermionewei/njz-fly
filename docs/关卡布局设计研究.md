# 横版卷轴关卡布局研究：障碍物、猪猪、应援棒

更新时间：2026-10-28
状态：已按路线 A（手工片段库 + 导演）+ C（按歌曲段落编排）实现，代码见 `components/levelSegments.ts`；手机采用强制横屏。BGM 实测约 109 BPM。

> 术语：**应援棒** = 白色兔子形状的可收集物（相当于金币）；**水管** = 障碍物（横放/竖放，碰到掉血）；**猪猪** = 站在横向水管上来回走的敌人。

---

## 0. 先说结论（5 条）

1. **成熟的横版跑酷/飞行游戏几乎都不是"随机放"，而是"手工设计的小片段 + 规则拼接"。** 程序只负责挑选、排序、镜像和微调；片段本身是设计师逐个摆出来的，每个片段只讲一件事。
2. **布局的最小单位应该是"一屏 / 一小节"，而不是"一根水管"。** 每一屏有一个明确的主题（"钻缝"、"打猪"、"吃一大片"、"上下绕"），玩家一眼能读懂它在考什么。
3. **应援棒不是装饰，它是"语言"。** 它有 5 种职责：指路、标记安全区、奖励冒险、奖励打猪、填充休息段。同一屏里应援棒的职责要清楚，最重要的一条规则：**应援棒永远不能把玩家引向必然受伤的位置。**
4. **紧张和放松要交替出现。** 好的节奏不是一路变难，而是"教 → 练 → 变化 → 放松"循环；参考图里有整屏只有应援棒、没有障碍的"奖励屏"，也有整屏只有障碍、没有应援棒的"考验屏"。
5. **我们的游戏有一个别人没有的优势：一局长度固定（BGM 约 191 秒，播完结算）。** 这意味着我们不是无限跑酷，而是"一首歌 = 一关"。可以像《雷曼：传奇》的音乐关一样，按歌曲段落（前奏/主歌/副歌/桥段）编排强度，让高潮和副歌对上。

## 1. 现状诊断：为什么现在的摆放"不够聪明"

当前实现在 `components/FlightGame.tsx`：六条固定航道（屏高 14%–86%），19 个 encounter 模板（`rest`、`switch-up`、`zigzag`、`pincer`、`coin-grid`、`cage-reward`、`patrol-duet` 等），加上镜像、随机种子、可达性验证。已有的 `docs/encounter-design-methodology.md` 方向不错，但落地后仍有这些问题：

| 问题 | 表现 | 根因 |
| --- | --- | --- |
| 障碍物的"词汇量"太少 | 竖管永远是 120px 宽、约 34% 屏高；横管永远是 250×82 | 只有两种尺寸，所以无论模板怎么排，画面看起来都差不多 |
| 每屏没有主题 | 玩家感觉是"一根管子接一根管子"，而不是"一个个关卡片段" | 生成单位是"事件"（某条航道被堵），不是"一屏的设计意图" |
| 应援棒是事后补上的 | 先放水管，再沿着安全航道画一条曲线放应援棒 | 应援棒只承担"指路"一种职责，没有冒险奖励、打猪奖励、整屏奖励 |
| 缺少极端对比 | 很少出现"整屏全是应援棒"或"整屏只有障碍"的段落 | 每个模板都同时塞了水管 + 应援棒，强度被平均化 |
| 猪猪只是附加物 | 猪站在横管上来回走，但玩家不打它也照样过 | 没有设计"打猪才能拿到奖励 / 才能走更好的路线"的选择 |
| 和音乐无关 | 片段随距离生成，与歌曲段落无关 | 没有利用"一局 = 一首歌"的特点 |

## 2. 业界方法论

### 2.1 手工片段 + 规则拼接（几乎所有成熟跑酷的做法）

- **Spelunky**：每层是 4×4 房间网格。生成器先走出一条"一定能走通的主路线"，再给每个房间按"它在路线上的位置"挑一个**手工设计的房间模板**，模板内部再带少量概率性的格子（比如"这里 30% 概率有尖刺"）。随机只发生在**安全的范围内**。
- **Jetpack Joyride**：应援棒对应的金币会排成箭头、文字等图形；电网障碍是成组设计的。一位参与该游戏地区版本的关卡设计师公开说，他们手工做了 **120 个 pattern**，用来训练玩家各种移动方式。
- **学术上的 chunk 方法**（SBGames 2013，无尽跑酷程序化关卡）：把关卡切成固定宽度的 chunk，先定义难度曲线，再生成 chunk、评估每个 chunk 的难度，最后按曲线实时插入。

**对我们的启示**：不需要"更聪明的随机"，需要的是**一个手工设计的片段库**，再加一个"导演"按强度曲线挑片段。

### 2.2 韵律组（Rhythm Groups）

Gillian Smith 等人做的 **Launchpad**（2D 平台关卡生成器）有一个核心概念：**节奏就是玩家手上的感觉**，比如"连续三个小跳"或"三个慢悠悠的大跳"。它的流程是：

1. 先生成"节奏"（一串动作：移动 / 跳 / 等待），节奏有长度、类型（规律、摇摆、随机）、密度（低/中/高）；
2. 再生成恰好匹配这个节奏的地形；
3. 每个韵律组之间用**休息区**连接（没有任何操作要求的平地）。

**对我们的启示**：设计一屏时，先想清楚"玩家的手要做什么"（按上 0.5 秒 → 停 → 按下 1 秒 → 连按攻击 3 下），再去摆水管、猪和应援棒。动作序列是主体，物件只是为这个动作服务。

### 2.3 教 → 练 → 变 → 收（起承转合）

任天堂《超级马力欧 3D 世界》的关卡用的就是"起承转合"（Kishōtenketsu，总监林田宏一提到过）：

- **起**：在不会失败的安全环境里介绍一个新机制；
- **承**：在稍有风险的情况下练习它；
- **转**：加入一个变化，让这个机制以意想不到的方式出现；
- **合**：收尾，然后**扔掉这个机制，换下一个**。

**对我们的启示**：每个"主题屏"在一局里不要只出现一次就算了，应该成组出现：第一次很简单，第二次加难度，第三次有变化，然后换主题。这正是"新鲜感"的来源——不是每屏都不同，而是**每个主题有发展、然后退场**。

### 2.4 应援棒（金币）放置的规则

综合马力欧制作工坊教学、《饼干跑》（Cookie Run）的果冻设计和一项学术研究：

**应援棒可以做的事：**
- **指路**：一串应援棒画出能安全穿过障碍的路线（《饼干跑》的果冻大部分时候就是在提示前方障碍和可通过的路径）；
- **标记安全区**：告诉玩家"这里可以停"；
- **定义可选挑战**：放在需要多一次操作才能拿到的位置，奖励敢冒险的玩家；
- **画形状**：箭头、字母、心形，传达信息或制造惊喜；
- **偶尔"骗人"**：《饼干跑》也会故意让果冻路线有点误导，考验玩家判断。这要非常克制，只在后半段少量使用。

**应援棒必须遵守的事：**
- 能看见的应援棒就一定能吃到；
- **绝不把玩家直接带进障碍或伤害**；
- 服务于当前这屏的挑战，不要分散注意力；
- 开局前 30 秒不要把奖励放在危险位置，否则玩家学到的是"挫败"而不是"探索"。

**一项研究的结论**（Sarkar 等，2018）：沿着"玩家自然会走的路线"放的金币，比设计师随手放或随机放的金币，玩家吃得更多、更快。也就是说，**应援棒曲线要符合角色真实的运动能力**。

### 2.5 敌人：每一波都是一道小谜题

横版射击（STG）的经验：

- **每一波敌人应该像一道有优雅解法的谜题**，而不是一堆让人乱打的目标；每一波要和上一波有逻辑联系；
- 第一波要"有趣但不难"，用来介绍这一关的主题；
- **玩家永远要有活路**；
- 玩家喜欢**认出模式**、觉得自己很聪明，所以敌人的出现方式要有形状和规律；
- 敌人行为可以拆成**入场 → 行动 → 退场**三段来设计。

### 2.6 模式词汇表

Dahlskog 和 Togelius 分析《超级马力欧兄弟》关卡，把布局拆成**微观 / 中观 / 宏观**三层模式，归为 5 大类、23 种：敌人（单个、2 只一组、3 只一组……）、坑、山谷、多路线、阶梯。生成关卡时，把"出现了多少种已知模式"作为评分标准。

**对我们的启示**：先给我们的游戏建一份"模式词汇表"，再用它来检查一局里各种模式是否都出现了、有没有某一种出现太多。

### 2.7 张弛曲线

跑酷常见的节奏是：**安全段 + 一簇高强度决策**交替出现。障碍常用三连、之字、高低交替等**重复母题**，让玩家能"学会语法"、靠认出模式变强，而不是纯靠反应。生成时要保证相邻障碍有最小间距。

## 3. 参考截图拆解（10 帧）

| # | 画面 | 这屏的"主题" | 可以借鉴的点 |
| --- | --- | --- | --- |
| 1 | 一根长横管，4 根应援棒排在管子**上方**；下方一根短竖管，竖管旁有 1 根应援棒 | 选上还是选下 | 应援棒"贴着"障碍边缘排，告诉你"这条路安全"；上面奖励多，下面奖励少 |
| 2 | 4×4 网格，应援棒和曲奇交错，**没有任何障碍** | 奖励屏 / 休息 | 整屏纯奖励；网格让玩家自由选一行扫过去 |
| 3 | 上方 L 形管从天花板垂下，下方一根短管；应援棒**斜着**穿过两管之间 | 钻缝 | 应援棒就是穿缝路线，斜率符合角色速度 |
| 4 | 左上一大块管子，曲奇排成**两段弧线** | 波浪收集 | 弧线让玩家上下摆动，手感很好 |
| 5 | 几块短管错落像台阶，中间散着小道具 | 绕行 | 障碍是"小块"而不是长条，形成多条可选路线 |
| 6 | 猪站在**短竖管顶上**，左右各有短管，应援棒在管顶 | 打猪 | 猪的位置就是射击目标；打掉后上方路线打开 |
| 7 | 高处有大块管子，猪站在中间一根短管上 | 打猪 + 绕行 | 敌人放在必经区域附近，不打就要绕远 |
| 8 | 管子围成**方形笼子**，里面 1 根应援棒；右侧上下各一大块管墙形成走廊；下方一排曲奇 | 冒险奖励 | 笼子是"可选挑战"，下面的曲奇是安全路线 |
| 9 | 猪在两层横管之间，被打中出特效；应援棒在右侧上下 | 打猪后奖励 | 打掉猪 → 奖励在后面 |
| 10 | 一堆**倾斜**的管子散落 | 碎片阵 | 视觉上制造"混乱感"，但缝隙其实很大，是一种"看起来难、实际公平"的变化 |

**从截图提炼的规律：**

1. **障碍物尺寸丰富**：短块（约 1 航道）、长横管、整面墙、L 形、笼子、倾斜碎片。这是"不重复感"最直接的来源。
2. **每屏只考一件事**，而且一眼能看懂。
3. **强度对比极端**：有纯奖励屏（#2、#4），也有纯障碍屏（#10）。
4. **应援棒紧贴路线**：贴着管子边缘、穿过缝隙、排成弧线，几乎从不"漂浮在无意义的位置"。
5. **敌人站的位置有讲究**：在玩家路线上或旁边，不打就要多绕一下。
6. **道具和障碍不重叠**，安全路线始终清晰。

## 4. 映射到我们的游戏

### 4.1 障碍物：扩展"词汇"，而不是加更多模板

建议的水管形态（都基于现有水管渲染器 `pipeArt.ts`，只改尺寸和组合）：

| 形态 | 说明 | 用途 |
| --- | --- | --- |
| 短块 | 约 1 航道高的短管 | 台阶、零散障碍、猪的站台 |
| 长横管 | 现在的横管，可以有长短两档 | 分割上下路线，猪巡逻 |
| 高墙 | 从顶部或底部伸出，占 2–3 航道 | 强制换道 |
| 门 | 上下各一根，中间留缝 | 钻缝 |
| L 形 / ⌐ 形 | 竖管 + 横管拼接 | 制造"拐弯"路线 |
| 笼子 | 4 段管围成方框，留一个口 | 冒险奖励 |
| 阶梯 | 3–4 个短块斜向排列 | 引导连续换道 |
| 碎片阵 | 少量倾斜的短管 | 后期视觉变化（碰撞盒需要按真实形状计算） |

### 4.2 猪猪：从"附加物"变成"选择题"

- **站位**：站在横管或短块的顶面上，巡逻范围 ≤ 站台长度。
- **三种用途**：
  1. **挡路型**：猪在最顺的路线上，打掉就直接过，不打就要绕远；
  2. **守奖励型**：猪在一串应援棒前面，打掉才能安心吃；
  3. **成组型**：2–3 只排成一列或台阶状（参考马力欧的"2 只一组 / 3 只一组"），让玩家连续射击。
- **必须遵守**：
  - 永远有"不打也能过"的路线（只是更绕或奖励更少）；
  - 猪出现到进入玩家所在位置之间，至少要有一次攻击冷却（280ms）+ 瞄准余量的时间；
  - 第一次出现的猪不动，后面才开始巡逻。

### 4.3 应援棒：给每一串定一个角色

| 角色 | 形状 | 数量 | 放在哪 |
| --- | --- | --- | --- |
| 指路 | 直线 / 斜线 / 弧线 | 5–8 | 沿安全路线，穿过缝隙 |
| 冒险奖励 | 短串、笼内、紧贴管边 | 3–5（但分值更高或更集中） | 需要多一次操作才能吃到 |
| 打猪奖励 | 直线 | 4–6 | 猪的后面，打掉猪后顺势吃 |
| 奖励屏 | 网格、波浪、心形、文字 | 15–30 | 没有障碍的休息屏 |
| 面包屑 | 稀疏单个 | 1–3 | 两个片段之间的过渡 |

**几何约束（由角色真实能力算出）**：

- 角色纵向最大速度 310 px/s，世界横向巡航速度 410 px/s，所以理论最大斜率约 0.76（约 37°）。**应援棒斜线的斜率建议 ≤ 0.55**，留出加减速余量，否则看起来能吃、实际吃不到。
- 应援棒间距保持现在的 52–64px，形成连贯的"线"。
- 应援棒和水管碰撞盒之间至少留"角色半高 + 12px"。

### 4.4 一屏 = 一个片段

建议把片段宽度设为**约一屏宽**（桌面横屏约 1000–1300px），每个片段有：

```
主题（钻缝 / 打猪 / 奖励 / 绕行 / 阶梯 / 冒险……）
强度（0 休息 · 1 简单 · 2 中等 · 3 高潮）
动作序列（玩家的手要做什么）
水管 / 猪 / 应援棒的位置（手工摆放，按航道坐标）
入口航道范围、出口航道（用于和前后片段衔接）
可变参数（镜像、上下平移一条航道、有没有猪、应援棒用哪种角色）
```

## 5. 关键机会：一首歌就是一关

BGM《Supernatural - 250 Remix》约 **191 秒**，播完就结算。按巡航速度 410 px/s 算，一局大约飞 **7.8 万像素**，大约 70–80 个片段。

这跟无尽跑酷不一样，更接近"有开头有结尾的一关"。可以按歌曲结构来安排强度（具体时间点需要对着歌曲标注）：

| 歌曲段落 | 关卡强度 | 适合的片段 |
| --- | --- | --- |
| 前奏 | 0–1 | 教学：单门、静止猪、应援棒指路 |
| 主歌 1 | 1–2 | 换道、阶梯、第一次打猪 |
| 预副歌 | 2 | 越来越密的门，制造期待 |
| **副歌 1** | **3 → 0** | 高潮片段，紧接一个奖励屏（大片应援棒） |
| 主歌 2 | 2 | 引入新形态（笼子、L 形、巡逻猪） |
| **副歌 2** | **3** | 更难的组合 |
| 桥段 | 1 | 安静的奖励/休息 |
| **最终副歌** | **3** | 全部机制混合 |
| 尾奏 | 0 | 大片应援棒"谢幕"，可以拼出 NJZ 字样或爱心 |

还可以把片段对齐到**小节**：如果确认了 BPM，就能让每个障碍正好落在拍点上，玩家会觉得"操作跟着音乐走"。

## 6. 两条实现路线

### 路线 A（推荐）：手工片段库 + 导演

1. 先手工设计约 **30–40 个片段**，覆盖第 4.4 节的主题，每个主题有 2–4 个难度版本；
2. "导演"按歌曲时间线挑片段：前奏用教学片段，副歌用高强度片段，每个高潮后必接休息/奖励；
3. 每个片段支持镜像、上下平移、有没有猪等变体，一共能组合出几百种画面；
4. 最近 N 个片段不重复主题；
5. 保留现有的可达性验证，作为所有片段的安全检查；
6. 做一个开发用的"片段预览页"，单独查看、调整每个片段。

**优点**：每屏都是设计过的，质量可控；新鲜感来自主题的轮换。
**缺点**：前期要手工摆片段。

### 路线 B：继续纯程序生成，只加更多规则

在现有 encounter 系统上加障碍形态、应援棒角色、强度曲线。

**优点**：改动小。
**缺点**：很难做出参考图那种"每屏都有想法"的感觉，容易重新回到"看起来随机"。

### 路线 C：固定编排整首歌

像音游谱面一样，把整首歌 191 秒的布局完全手工写死。

**优点**：体验最好，可以精准卡拍。
**缺点**：每局都一样，重玩性低；工作量最大。

**我的建议是 A，并借用 C 的思路**：导演按歌曲段落挑片段，片段对齐小节。这样既有"音乐关"的高潮感，每局又略有不同。

---

## 7. 需要和你讨论的问题

1. **路线选择**：A（片段库 + 导演）是否 OK？还是你更想要 C（每局一样、卡拍精准）？
2. **每局要不要一样**：玩家每次重开，看到的关卡是一样的、还是有变化？
3. **障碍物形态**：第 4.1 节的形态里，哪些你想要？倾斜碎片阵需不需要（碰撞判定会更复杂）？
4. **应援棒分值**：要不要所有应援棒都 +10，还是"冒险奖励"那串分更高？还是先都一样？
5. **猪猪的数量和行为**：保持"只在横管上巡逻"，还是也可以站在短块上不动、或者 2–3 只成组？
6. **手机竖屏的视野问题**：竖屏时画面很窄，玩家右侧能看到的距离可能只有 300px 左右，按 410 px/s 只有约 0.7 秒反应时间。是要求手机横屏玩，还是竖屏时降低速度 / 缩小画面 / 用更简单的片段？
7. **BGM 的 BPM 和段落时间点**：你知道这首 Remix 的 BPM 吗？如果不知道，我可以先标注段落时间点再对齐。
